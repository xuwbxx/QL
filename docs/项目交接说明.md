## 4. 领域模型与核心术语

### 4.1 混凝土梁

- **浇筑组（CastingGroup）**：一个梁的预制单元。
- **节点/端面（Node / Joint）**：设计坐标按节点导入；`N` 个节点派生 `N-1` 个梁段。
- **梁段（Segment）**：`SegmentName = "{Node1}-{Node2}"`，`SegmentIndex` 等于算法入参 `M`（第 `m` 段跨端面 `m..m+1`）。
- **设计坐标 source**：Excel 原始导入值，`biz_concrete_beam_design_coordinate_source`。
- **设计计算 calculation**：下游使用的计算结果，`biz_concrete_beam_design_coordinate_calculation`。
- **归一化展示**：source 做 K 归一化、**不叠加 camber** 的展示结果；**不落库**，按需现算。
- **预拱度 camber**：`biz_concrete_beam_camber_source` / `biz_concrete_beam_camber_calculation`。
- **项目 A/B/C/H**：`biz_concrete_beam_config.OffsetA/OffsetB/OffsetC/OffsetH`，全局参数，进入立模/归一化算法。
- **测点偏位 bo**：每段的 `aNE/aNW/aSE/aSW/cN/cS/bNE/bNW/bSE/bSW`，**只在 `St=1`（实测修正/as-cast）使用**；`St=0`（setup/理论）不消费 `bo`。
- **St**：
  - `St=0`：仅理论放样/立模 setup，不做实测修正；
  - `St=1`：实测修正，输出 as-cast（浇筑坐标）。
- **`PerfectCast`**：代码里是 St=0 的理论 setup 计算；**不要把它等同于“精度匹配”**。算法本身都会计算，`print('perfect cast')` 是输出段。
- **上游锁定**：`biz_concrete_beam_segment` 有有效填报后，项目 A/B/C/H、设计坐标、预拱度都不允许再改；判据 `HasSurveyData()`，服务端 `EnsureSurveyEditable` 兜底。

### 4.2 混凝土梁 bo 的关键结论（已和算法编写人确认）

- 算法里的“长度”= **joint 上边缘点之间的距离**，不是测点之间的距离，所以 **setup 长度不需要 bo**。
- `bo` 只在 `St=1` 的 `zeroerr` / `oneerr` 里使用，计算 as-cast；`St=0` 不消费。
- `oneerr` 的 bo 是 **13 项**：
  `[aNE1, aNW1, cN1, aNE2, aNW2, aSE2, aSW2, cN2, cS2, bNE2, bNW2, bSE2, bSW2]`
  - 上一段 N 部分只有 **a/c**，**没有上一段的 b**；
  - 四个 b 都是本段的。
- `zeroerr` 的 bo 是 **10 项**：本段 `aNE/aNW/aSE/aSW/cN/cS/bNE/bNW/bSE/bSW`。
- b 的用法：
  - `KCB[1] = BSE2`、`KCB[7] = -BSW2`（本段南侧 b）；
  - `KCF[1] = KCF[4] + BNE2`、`KCF[7] = KCF[4] - BNW2`（本段北侧 b）。
- 参考算法文件：`D:\WorkSpace\2026\程伟项目\周思成\代码及说明8.15\b-1_20261019.py`（最新版；不含老算法）。
- `UseB` 分支：勾选【已有实测 b 值】走 b 四角；不勾选走老的 `B`/中间量表达式。

## 5. 混凝土梁：设计坐标 / 预拱度（最近重点）

### 5.1 当前交互流程

1. **上传 Excel**
   - 只解析、校验，写入服务端 **preview token**（`IMemoryCache`，30 分钟滑动过期）；
   - **不写 source、不写 calculation**；
   - 设计表格显示 preview token 的数据：归一化未勾选显示 source，勾选显示归一化结果（不叠加 camber）；
   - 取消上传时删除 token，数据库不变（可回滚）。

2. **切换【归一化】**
   - **直接刷新 datatable**：
     - 未勾选 → 显示 `source`；
     - 勾选 → 显示 **`Calculate(source, B, null, true)`** 的结果，即 source 的归一化结果、**不叠加 camber**；
   - 结果现算，**不落库**；
   - 与【包含预拱度】无关。

3. **切换【包含预拱度】**
   - **不改变 datatable 展示**；
   - 只改草稿值，确认时影响 `calculation`。

4. **点击【确认】**
   - 一个事务：写 `source` + 写 `calculation`；
   - `calculation` 按下面的四象限生成；
   - 更新 `biz_concrete_beam_config.ElevationIncludesCamber` / `Normalize`；
   - 开关【预拱度】页签；
   - 删除 preview token。

5. **确认后修改**
   - 只要【设站及测量】还没有提交过数据（`hasSurveyData == false`），仍允许修改【归一化】/【包含预拱度】；
   - 点 Apply 会基于已保存 `source` 重新生成 `calculation`，并作废下游 as-cast；
   - 有设站数据时服务端 `EnsureSurveyEditable` 拒绝。

### 5.2 calculation 四象限（每次确认都写）

| normalize | includeCamber | calculation 内容 |
|---|---|---|
| `true` | `true` | K 归一化（source 已含 camber，不再叠加） |
| `true` | `false` | K 归一化 + camber；camber 缺失/节点不匹配时用 **0 行补齐**，按 +0 算，不报错 |
| `false` | `true` | 不归一化，`source` 原样复制（9 个坐标） |
| `false` | `false` | 不归一化，`source` 的 `ZE/ZC/ZW` 加 camber 的 Z；缺失 +0，不报错 |

补充：
- `calculation` **不会为空**；
- 缺 camber 时保存成功，返回 `RequiresCamber=true`，前端提示“请填报预拱度”，**不自动跳转**预拱度页签；
- 重新上传设计坐标**不清空已上传的 camber**；节点匹配就复用，不匹配按 0；
- 预拱度页签点确认也走同一矩阵（normalize 决定 K 或 source+camber）；
- `biz_concrete_beam_config.Normalize` 保存上次确认的归一化模式，用于刷新后回显、以及项目 B 变化时按同一模式重算。

### 5.3 实现要点

- `ConcreteBeamImportPreviewStore`：`IMemoryCache`，key 前缀 `concrete-beam-import-preview:`，30 分钟 `SlidingExpiration`；按账号 + 浇筑组 + 类型校验。
- `DesignImportPreviewList` / `DesignCoordinateList` 增加 `Normalized` 入参：
  - `Normalized=true`：`Calculate(sourceRows, config.OffsetB, null, true)`；
  - 预览用 preview token 行，确认后用 source 行；
  - 不写库。
- `ConfirmDesignImport` / `ConfirmDesignCamberSetting` / `ConfirmCamberImport` 使用同一四象限逻辑。
- `ConcreteBeamDesignCalculator.ApplyCamberToSource`：不归一化时，source 的 Z 加 camber 的 Z。
- `ZeroCamberRows`：给无 camber 的归一化补 0 行，避免 `Calculate` 报“请先导入预拱度”。
- 设计页签的【打印/预览】读已落库 `calculation`；存在 preview token 或草稿变化时禁用，避免看到旧值。

## 7. 钢梁：顶推线形管控（最近重点）

### 7.1 核心表

- `biz_steel_beam_theoretical`：理论测点。
- `biz_steel_beam_measure_batch`：实测批次（`PushCount`、`MeasureTime`）。
- `biz_steel_beam_measured`：现场实测点（只存真实上传，不做补全）。
- `biz_steel_beam_derived_coordinate`：**滚动快照**，按 `TheoreticalID` 逻辑唯一：
  - `MeasuredID > 0`：有实测来源；
  - `MeasuredID = 0`：段内补全（不是实测）；
  - `BatchID = 0`：纯补全；
  - 一行 = 一个测点的最新坐标。

### 7.2 上传与 replay

- 同一个 `PushCount` 允许多个 batch，**以 `MeasureTime` 最新的 batch 为准**；更早的 batch 会被 supersede（`Status=-1`），更早 MeasureTime 的上传直接拒绝。
- 每次上传后从 `PushCount=0` 到当前 **全量 replay**：
  - 每个 PushCount 取最新 batch；
  - 逐批生成滚动快照；
  - 最终按 `TheoreticalID` upsert，旧行 `Status=-1`。

### 7.3 每批推算规则

1. **本批上传段（touched）**
   - 上传点：真实实测，`MeasuredID=本批 measured.ID`，`BatchID=本批 batch.ID`；
   - 段内缺失点：
     - 以前实测过（上一快照 `MeasuredID>0`）：用刚体变换 **T** 从上次坐标搬运，保留原 `MeasuredID`，`BatchID=当前`；
     - 从未实测：用本段设计坐标 + 本段本次上传点做 **逐段 Gescha** 补全，`MeasuredID=0`、`BatchID=0`。
2. **出胎段**（上一快照里、本批未上传的段）
   - 全部点用 T 搬运；`MeasuredID` 保留，`BatchID` 按是否有实测来源决定。
3. **T 的算法**
   - 上次完整集直接来自上一批滚动快照；本次完整集由本段设计坐标 + 本次上传点逐段补全；
   - 用两份完整集的同名点拟合 **一个全局 T**（多个重复梁段合并）；
   - scale 固定 1.0；
   - 重复段判定：上一次该段 `MeasuredID>0` 的点 ≥3，且本次该段上传点 ≥3；
   - `push0` 没有上一次，T 不存在，只做段内补全。
4. **失败条件**
   - 某段本批有缺失点但上传点 <3 → 报错；
   - 有搬运目标但没有可用重复段 → 报错；
   - 失败会回滚整个导入事务。

### 7.4 监控计算

- 段下拉返回**全部**梁段，带 `(已拼装)/(待拼装)`：
  - 已拼装 = 该段至少有一个 `MeasuredID>0` 的点；
  - 待拼装 = 没有。
- 已拼装段：**直接读 derived 快照**，不再重算；快照缺失 → 报错提示先 `RebuildDerived`。
- 待拼装段：用快照中 `MeasuredID>0` 的点做 P/Q，D=待拼装段设计坐标，Gescha 预测。
- 允许混合选择，但所选梁段必须按 `DistanceFromStart`/`PositionOrder` **连续**，不能跳段。

### 7.5 误差分析

- 读当前滚动快照全部 active 行；
- `MeasuredID=0` 的补全点：`ZError=null`；
- 前端折线图 `connectNulls:false`，显示空位/断点，而不是 0。

### 7.6 重建接口

- 单根：`POST /Biz/SteelBeam/RebuildDerived?girderId=...`
- 批量：`POST /Biz/SteelBeam/RebuildDerivedBatch`
  - body `{ "projID": 123 }` 或 `{ "girderIDs": [1,2,3] }`；
  - 只处理 `BeamType=0`（钢梁）、`Status!=-1`；
  - 逐梁独立事务，返回逐根 `{girderID, girderName, success, message}`。
- UI 上“重算推算坐标”按钮当前隐藏；接口保留。

## 9. 部署与排错

### 9.1 编译

- 只验证 Service：`dotnet build Service\Service.csproj`（0 error 为通过）。
- 完整 Web 编译可能报 **MSB3021 / MSB3027**（运行中的站点锁 `Service.dll` 等），不是代码错误。
- 前端 JS：`node --check <file>`。
- cshtml 里 Vue 事件必须双 `@`：`@@click`、`@@change`、`@@input`，否则 Razor 会把单 `@` 当指令。

### 9.2 部署

1. 整体覆盖上传到 `/var/www/qlprea/`（FTP 用**二进制模式**，避免 dll 损坏/Linux 大小写问题）；
2. **必须重启 Jexus**：`/usr/jexus/jws restart`；
   - 不重启会出现 `Could not load file or assembly 'MigraDoc.DocumentObjectModel, Version=6.2.4.0'`。
3. 不要用 `nohup` 裸跑 dotnet，会与 Jexus 抢端口；临时调试后 `pkill -f "QL.PreAssembled.dll"`。

### 9.3 排错顺序

1. 服务器本机 `curl http://127.0.0.1:5020/`（或 siteconf 的 AppPort）应 302；
2. 服务器用对外 IP 自测 80 端口应 302；
3. 前两步正常 → 是客户端到服务器的网络/代理/网安策略问题（不是应用问题）。
4. 日志：`/tmp/qlprea.out.log`、`/tmp/qlprea.err.log`。
